KLOR polydactyl — working keymap

Four layers over 44 positions. NAV has been removed and NUM is now XTRA — a scratch layer for whatever gets reached for often. Layers chain rather than combine: BASE into XTRA into FN into SYS, one key deeper each time.

Before you change anything

Edit the right file

config/klor.keymap is the live one. The identically-named copy under boards/shields/klor/ is shadowed by it and does nothing — editing that one produces a build with no visible change.

The count that must hold

Every layer needs exactly 44 bindings and 2 sensor-bindings, left encoder first. Layer indices are positional too: deleting a layer renumbers every layer below it, so the #define block and the node order must stay in sync.

No local build

There is no west, docker, or pip here — CI is the only compiler. Push, open the Actions tab, download the firmware artifact, double-tap reset on each half and drag the matching .uf2 onto the drive.

Two hold-taps, one in use

spc drives position 39 — tap Space, hold Super. It is not the built-in &mt, whose hold-preferred flavour resolves to the hold the moment another key is pressed inside the tapping term, turning "the quick" into Super+q. tap-preferred plus require-prior-idle-ms is what lets a hold-tap survive on the most-pressed key on the board.

hm is defined and deliberately unused. Swap &kp F for &hm LSHFT F on any alpha to get home-row mods.

One combo

Q + W (positions 0 and 1) sends Tab, 50 ms window; Escape has its own key at 10.

There was a 38 + 39 Super combo. It was removed: a combo needs both keys inside 50 ms every time, which is poor for a modifier you hold through a chord, and it swallowed both presses so XTRA never engaged. Super is a hold-tap on 39 now.

What ZMK will not do

No speaker and no haptic — those are QMK-only on this PCB.

Mainline ZMK has only whole-strip underglow, so this config replaces it with a custom module: white at 10%, and the LED under a pressed key rises to 60%. That makes every &rgb_ug binding inert — they still build, because ZMK declares the behaviour unconditionally and gates only the driver, which is how twelve dead keys sat on SYS unnoticed. They have been replaced by &rgb on position 5, an on/off switch that reaches both halves and is remembered across reboots.

Both OLEDs draw their own half of this keymap, invert the key you press, and follow the active layer. The right one only manages the last of those because the layer is pushed to it: a peripheral never runs the keymap, so the central sends the layer index across the split link in a behaviour parameter.
